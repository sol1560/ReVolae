# iPad 指针校准库

HID 鼠标只发送相对增量，但调用方要点截图里的绝对坐标。iPadOS 又会按单个报文的速度和幅度放大位移，所以不能用一个固定比例换算。

## 算法

1. 在屏幕中部依次发送长度 `1, 2, 4, 8, 12, 16, 24, 32, 48, 64, 80` 的水平和垂直增量。
2. 每次发送前后，由 iPad app 从校准页面的指针事件或截图光标检测得到 `from`、`to`。
3. `fitCalibration()` 按增量长度分桶，取四个方向观测位移的中位数，剔除终点在边缘的撞墙样本，再强制曲线单调。
4. `toDeltas()` 对曲线做分段线性反解。每步只发整数 HID 增量，并在附近搜索误差最小的整数二元组；长距离拆成不超过已测最大幅度的多个报文。
5. 当前坐标不可信时用 `homeAndMove()`：连续往左上移动，靠屏幕边界把位置归零，再从 `(0,0)` 去目标。这会短暂显示指针撞向左上角，不能用于拖拽中途。

选择分段线性而不是多项式，是因为加速曲线应保持单调，而高阶多项式容易在样本之间过冲。此模型假定同一设置下各方向近似径向对称。改变“指针速度”、显示缩放或方向后要重新校准。

## 接口

```ts
const model = fitCalibration(samples, {width: 1024, height: 768});
const moves = toDeltas({x: 100, y: 200}, {x: 800, y: 600}, model);
const fromUnknown = homeAndMove({x: 800, y: 600}, model);
```

每个样本格式：

```json
{"delta":{"x":16,"y":0},"from":{"x":500,"y":300},"to":{"x":520,"y":300}}
```

调用方应把返回序列放进一次 `/macro`，相邻 HID 报文间隔 15 ms，并在最终点击前等待一帧（建议 30 ms）。截图像素和 UIKit 点可能不同，样本与目标必须使用同一坐标系。

## 检查

```sh
bun install
bun test
bunx tsc --noEmit
```

测试中的“假 iPad”使用非线性单调加速曲线，并覆盖 100 个固定随机目标、撞墙归零和越界目标。它验证算法，不替代真机测量。
